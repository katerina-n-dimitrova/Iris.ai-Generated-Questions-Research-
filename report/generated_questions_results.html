Generated questions results

Generated questions as a context-enrichment method for RAG retrieval — from a plain dense count sweep, through a vision-enriched arm, to BM25 / hybrid document expansion. SPIQA test-B.

What was tested

doc2query-style generated questions

Each chunk is expanded with LLM-generated questions it can answer; the questions are stored/indexed alongside the chunk but a question hit always maps back to its parent chunk — only the original chunk is returned as evidence. We sweep the number of questions per chunk (0/1/10/50/100), add a vision arm where figure/table chunks first get a gpt-4o-mini visual description, and finally feed the questions to BM25 / hybrid retrieval as document expansion.

  • Vision study set: 20 papers · 1026 chunks · 74 eval queries (all figure-answerable) · 216/216 figure units vision-enriched.
  • Embedder: huggingface Octen/Octen-Embedding-0.6B (dim 1024), no fine-tuning. LLM: gpt-4o-mini. Questions + vision descriptions cached.
  • Arms: novision = questions from the raw chunk text; vision = figure chunks carry a visual description before the chunk is embedded/BM25-indexed and before questions are generated.

Finding vision helps
Vision lifts retrieval most exactly where caption-only is weakest: at baseline the chunk vector now carries the chart itself (nDCG@10 +0.0276, Hit@1 +0.0811 vs novision baseline), and at q10 it gives the best dense config of the whole study — vision q10 = 0.6911 nDCG@10, 0.8514 Hit@5, 0.9189 Hit@10. Finding BM25 + vision win
Generated questions help sparse/BM25 more than dense (q10 BM25 0.6933 vs dense-append 0.6587). BM25 is strong even with no questions (captions are lexically distinctive). Stacking everything — vision descriptions feeding both the dense vector and the BM25 document — gives the best config of the whole study: vision q50_hybrid_expand = 0.7258 nDCG@10 (Hit@10 0.9054, MRR 0.6954) at 1.46× storage. Cheapest strong config: vision q10_bm25_expand = 0.7071 at 0.38× storage and ~2ms p95.
One exception
The only place vision doesn't help is baseline_bm25 (−0.0121 nDCG@10): pure lexical retrieval on the raw caption already matches the figure's key terms, so the extra visual prose adds a little noise. Everywhere questions or dense vectors are involved, vision wins.

Recommendation
Use generated questions (~q10) as BM25 / hybrid document expansion, with a vision description folded into figure chunks first. Questions add lexical anchors that BM25 matches verbatim; the vision step feeds both the dense and sparse sides; and RRF hybrid captures the lexical match the dense embedder misses. Go to q50 only if you need the last ~2 points of nDCG@10 and can pay ~1.46× storage.

Follow-up experiments: improving generated-question quality

question quality > question count

The first study showed that simply increasing the number of generated questions saturates — q10 is the sweet spot and q50/q100 add cost without much gain. So instead of adding more questions, these follow-ups hold the count at ~q10 and improve question quality and how questions are indexed: forcing question-type diversity, grounding questions in the chunk's exact lexical anchors, filtering out weak/duplicate questions, keeping questions in a separate index instead of polluting the chunk vector, adding a cross-encoder reranker on top of hybrid recall, and giving figure/table chunks a structured visual representation. Same 20-paper SPIQA test-B set (1026 chunks · 74 figure-answerable queries), same embedder (huggingface:Octen/Octen-Embedding-0.6B:dim1024), same LLM (gpt-4o-mini), cached outputs reused. Interpretation & recommendation

what moved retrieval, and what to use next
Which method helped most
Diverse question types did not help (0.6865 vs generic 0.6919, -0.0054). BM25-aware lexical grounding moved BM25 retrieval -0.0172 nDCG@10 (to 0.6761) — no gain, confirming whether the win is lexical. Filtering matched the unfiltered q10 at ~40% fewer questions (a cost win, not a quality gain) (0.6924 vs 0.6919, +0.0005) — fewer-but-cleaner questions. Separate question index (RRF, no concatenation) = 0.6837 (-0.0082 vs hybrid append) — concatenation was already fine here. Cross-encoder reranking hurt nDCG@10 (0.606, -0.0859 vs hybrid) even though it gave the highest recall of any condition (Hit@10 0.9054) — the correct chunk is in the top-50, but a general-domain MS-MARCO reranker mis-orders scientific figure/table text and is far slower; first-stage recall was already the bottleneck, not ranking. Structured figure/table context = 0.7134 hybrid (+0.1006 vs baseline_dense) — structuring axes/values/methods helped multimodal retrieval. Overall best new config: structured_vision_q10_hybrid = 0.7134 nDCG@10 (+0.1006 vs baseline_dense) at 1.36× storage.
Recommendation
For future experiments, adopt structured_vision_q10_hybrid as the reference configuration. Concretely: filter candidates (drop generic/duplicate/ungrounded) to get the same quality at lower cost; use structured visual context (axes/values/methods) for figure/table chunks in multimodal papers.
